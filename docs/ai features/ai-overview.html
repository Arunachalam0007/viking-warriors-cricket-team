AI architecture (overview)

How every AI feature in the portal is put together: two free providers, one fallback model, read-only tools over the existing queries, and AI changes that only happen when an admin confirms them.

Pages never call an AI model. Texts are written once (after a sync or nightly) into ai_content and pages just read them, so the site stays fast and the free quota is spent only on new facts.

Design rules

  1. Postgres stays the single source of truth. The AI sees data only through tools that call the existing query functions (modules/stats/queries.ts, modules/finance/queries.ts), never raw SQL.
  2. Facts in, words out. Generated texts are written from a JSON of facts built in facts.ts; the prompt forbids inventing numbers. The facts hash decides when a text is out of date.
  3. Admin edits win (same as the rest of the app): an edited AI text has edited = true and is never overwritten.
  4. The AI never changes money on its own. Change tools build a preview from the database; only the admin's Confirm runs them, in one transaction, with an ai.* audit entry and a Google Sheet refresh.
  5. Public answers are limited to public data: no phone numbers, payments detail, expenses or cash holders; balances only if public_show_balances is on.
  6. Free tier only: two providers and a chain of models with separate quotas; no limit on questions (when one provider is full the other answers); a cap per background run.
  7. Tamil first: every text is written in Tamil and English; the team name is fixed as வைகிங் வாரியர்ஸ் in Tamil.
