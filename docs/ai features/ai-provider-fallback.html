AI feature

Gemini ⇄ Groq fallback

Every AI call goes to the admin's first provider; if it is out of quota, busy, failing or silent, the same call is answered by the other provider. It works both ways.

Purpose and access

read Admin → AI shows the providers, which models are resting, calls per provider today, and the last switches. Admins choose which provider is tried first.

How a call is answered

sequenceDiagram
  participant F as Feature (chat / job / scan)
  participant M as fallbackModel
  participant G as Gemini model
  participant Q as Groq model
  F->>M: generateText / streamText
  M->>G: request (timer 15 s stream / 45 s generate)
  alt answers
    G-->>M: first text or tool call
    M-->>F: stream (response.modelId = Gemini model)
  else 429 quota / 5xx / stall / bad key
    G--xM: error
    M->>M: rest that model, log ai_usage (ok = false)
    M->>Q: same request
    Q-->>M: answer
    M-->>F: stream (response.modelId = Groq model)
  end

“Groq first” in Admin → AI swaps the order (Groq's model, then Gemini's, …). Models that are resting move to the end of the list but are still tried if nothing else works.

Rest times

ErrorRest
429 / quota / rate limit (per minute)60 s
Daily quota (“per day”)3 h (Google resets at midnight US Pacific)
401 / 403 (wrong or revoked key)10 min
404 (model retired)24 h
5xx, “high demand”, no answer within 15 s (stream) / 45 s (generate)30 s
400 (bad request)no rest: the problem is the call, the next model still tries it

Rest state is kept in memory per server instance (Vercel may run several); the usage log in the database is what Admin → AI's numbers come from.

Why stream answers wait for the first word

Providers report quota and overload errors when the request starts, and Gemini sometimes accepts a request and then sends nothing. doStream reads the stream until the first real part (text, tool call or finish) before handing it on; until then, any error or the 15-second timer moves the call to the next model, so the visitor never sees a half answer from a failing provider. Pressing Stop aborts the call and does not try another model.

How to test

  • Break one key on purpose: GEMINI_API_KEY=x npm run ai:jobs -- 1 → the text is written by Groq; ai_usage shows a failed Gemini row then an ok Groq row.
  • Set “Groq first” in Admin → AI and ask AI-Viking-Bot anything: the answer shows “via Groq”.
