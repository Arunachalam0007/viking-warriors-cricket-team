Viking Warriors Team Portal

Architecture, data model, finance rules, sync, security, setup and operations for the Viking Warriors cricket team site.

CricHeroes team 2921535Match fee ₹50Finance from 1 Oct 2026Cash holder RahulNightly sync 23:30 IST

What this is

The Viking Warriors Team Portal is a Next.js web app for the Viking Warriors cricket team (CricHeroes team 2921535). It has two parts:

  • Public site — anyone with the link: dashboard, player profiles with photos, weekly / monthly / season leaderboards, matches and scorecards, match-fee finance with filters and Excel export, and reports.
  • Admin portal — login required (/admin): match fees per match and per player (played / not played, paid / not paid, waived, custom amount), payments, tournament and monthly collections, expenses and income, cash holders (Rahul by default), player names / phones / photos, settings, admins, sync logs and the audit trail.

Match and player data come from CricHeroes every night at 23:30 IST. Finance is calculated in the app's own database and mirrored month-wise into Google Sheets.

Finance rule: ₹50 (setting match_fee) per squad member for every completed or abandoned individual match on or after 1 Oct 2026 (finance_start_date). Tournament matches, upcoming matches and guests are never charged automatically; tournament money is collected through Collections.

Fee rule and ledger

isChargeableByDefault() in src/modules/finance/rules.ts: a match is chargeable when status = 'past' (completed or abandoned), kind = 'individual', and its IST date is on or after finance_start_date. reconcileMatchCharges() in ledger.ts then makes the match's match_fee charges equal "played members × fee_per_player":

  • played member without a charge → charge created (amount = fee_per_player);
  • existing charge not admin-locked → amount, date and description refreshed;
  • charge for someone who no longer should pay → deleted, unless it is admin-locked or already has money allocated (then it is kept for the admin to waive).

Balance per player = Σ non-waived charges − Σ payments. Payments settle charges through payment_allocations, oldest charge first (applyCredit()). Money not yet allocated is credit and is applied automatically to the next charge.

Worked example

StepWhat happensGopi's balance
1Gopi plays 4 Oct and 11 Oct individual matches → two ₹50 match_fee charges₹100 due
2Admin records a ₹150 UPI payment (received by Rahul) → ₹50 to 4 Oct, ₹50 to 11 Oct, ₹50 left as credit₹50 credit
3Gopi plays 18 Oct → new ₹50 charge; applyCredit() settles it from the credit₹0
4Admin creates a ₹400 tournament collection including Gopi₹400 due
5Admin waives the 18 Oct fee → its ₹50 allocation is freed and moved onto the tournament charge₹350 due

Statuses (chargeStatus()): paid (allocated ≥ amount), partial, unpaid, waived.

Admin locks: how the sync respects admin edits

Lock columnSet whenSync behaviour
matches.finance_lockedAdmin saves fee settings for a match (updateMatchFinance)Sync no longer changes kind, chargeable, fee_per_player
match_players.admin_lockedAdmin toggles Played or adds a player (setMatchPlayer)Sync never removes or changes that row
charges.admin_lockedAdmin changes amount or waives (setChargeAmount, setChargeWaived); all collection and adjustment chargesNever updated or deleted by reconcileMatchCharges()

Also: fee_per_player is only taken from settings while a match is new or not yet finished, so changing the default fee never rewrites past matches.

CricHeroes sync

See CricHeroes sync for detail. It reads three public pages (team matches, team members, each scorecard) and parses the embedded React Server Components payload. It does not use CricHeroes' private API key. Re-running is safe: matches are keyed by cricheroes_match_id, charges are unique per match + player, stats are upserted. Scorecards are re-read for 3 days after a match in case the scorer corrects them. Problems with single pages are recorded as warnings in sync_runs.summary; a failure to read the match list fails the run without touching data.

Google Sheet mirror

One-way, app → sheet (details). Tabs: Summary, one tab per month since 1 Oct 2026 (e.g. Oct 2026, laid out like the old "Normal match amount split": players down, match dates across), Collections, Payments, Expenses, Income. After every admin change the sheet is rewritten (5-second debounce so a burst of clicks causes one write) and it is rebuilt nightly. Other tabs in the sheet are left alone. If the sheet is not shared with the service account, the run fails with "Permission denied. Share the Google Sheet with … as Editor."

Excel export

GET /api/export/finance with the same filters as the Finance page (details). Public workbook: By player, By match, Charges (player sheets omitted when public_show_balances is off). Admin workbook (?scope=admin, admin session required) adds Payments, Expenses, Income.

Auth and security

  • Login: Supabase Auth email magic link (/login), only sent to emails in the admins table. Optional Google sign-in. Session cookies via @supabase/ssr.
  • Authorization: requireAdmin() (src/lib/auth.ts) runs in the admin layout, at the top of every admin page (layouts and pages render in parallel, so the layout alone is not enough) and inside every admin server action through adminAction(). proxy.ts also redirects anonymous visitors from /admin to /login before rendering.
  • Database: row level security is enabled on every table with no policies, so Supabase's public REST API cannot read or write anything. The server connects as the database owner.
  • Secrets: SUPABASE_SECRET_KEY, GOOGLE_PRIVATE_KEY, CRON_SECRET and the database URLs are server-only environment variables; the Settings page shows whether they are set, never their values.
  • Public vs admin-only: public — stats, matches, match fees and balances (switchable with public_show_balances), team-level fee charts. Admin-only — phone numbers, payments list, expenses, income, cash holders, fund balance, audit log, sync logs, admin Excel.
  • Audit: every admin mutation writes audit_log with before/after values.

Nightly job

vercel.json schedules /api/cron/nightly at 0 18 * * * (18:00 UTC = 23:30 IST). On the Hobby plan Vercel may run it any time within that hour. The route checks Authorization: Bearer $CRON_SECRET, runs runCricheroesSync("cron"), then syncSheet("cron") even if CricHeroes failed. Admins can run the same thing from Sync & logs.

Deployment

  1. Supabase: create a project (this one is in Singapore, ap-southeast-1, matching Vercel region sin1). Copy the Transaction pooler (6543) connection string into DATABASE_URL and the Session pooler (5432) one into DIRECT_DATABASE_URL, project URL, publishable key and secret key. In Auth → URL configuration set the Site URL to the Vercel URL and add https://<domain>/auth/callback to redirect URLs.
  2. Migrate: with the env set locally, run npm run db:migrate. This creates all tables, enables RLS, and seeds admin arunsha0007@gmail.com and cash holder Rahul.
  3. Google Cloud: create a project, enable the Google Sheets API, create a service account, download a JSON key. Put client_email and private_key in env. Open the team sheet → Share → add the service account email as Editor.
  4. Vercel: import the GitHub repo, add every env variable, deploy. vercel.json sets the region and the cron.
  5. First sync: log in at /login, open Admin → Sync & logs → Sync CricHeroes now, then Rebuild Google Sheet now.

Known challenges and limits

  • No official CricHeroes API. The sync reads public pages; a redesign of cricheroes.com can break it. Only src/modules/cricheroes/parser.ts should need changing (see the cricheroes-sync skill). Their terms may not allow automated reading, and they could block cloud IPs.
  • Latest 12 matches only. The public matches page lists the newest 12. A nightly run never misses matches, but if the sync fails for weeks while more than 12 matches are played, older ones must be added by hand.
  • Matches without a scorecard have no XI; the sync logs a warning and the admin adds players on the match-fee screen.
  • Name matching for fielding. Catches / stumpings / run outs are matched by name from dismissal text; unusual spellings can miss a credit.
  • Magic link must be opened in the same browser that requested it (PKCE). Supabase's built-in email sender is limited to a few emails per hour.
  • Free-tier limits: Supabase pauses after 7 idle days (nightly job prevents it); Vercel Hobby cron runs within the hour; Google Sheets API quota (the writer uses about 4–5 calls per rewrite).
  • Manual sheet edits are overwritten by the next sync — the app is the source of truth.

Roadmap (phase 2)

  • WhatsApp dues reminders: the notification_outbox table and players.phone are in place; a sender (click-to-chat links first, then WhatsApp Cloud API) will be added.
  • AI features and chatbot: to be started only when the team owner says so.
