Public page

Admin login

Email + password sign-in for admins, password changes and resets, and sign out. No emails are sent.

Purpose and access

public

Open to everyone; no login. Pages are rendered on the server on every request from the app database (never from CricHeroes directly).

URL and query parameters

URL / parameterMeaning
/login?next=/admin/feesLogin form. After login the admin goes to next (same-site paths only). Already-signed-in admins are redirected.
/login?error=not_admin|googleError message: signed in but not on the admin list / Google unavailable.
/admin/accountMy account: change your own password.
/auth/callback?code=…Only used by the optional Google sign-in.
POST /auth/signoutSigns out and returns to / (sidebar button).

Actions

  1. Admin enters email + password → server action signInWithPassword checks admins (isAdminEmail) and calls supabase.auth.signInWithPassword, which sets the session cookies. Unknown emails and wrong passwords get the same message ("Wrong email or password").
  2. New admins: Settings → Admins → Add admin with a starting password (addAdmin creates the Supabase login with auth.admin.createUser, email pre-confirmed). Forgotten password: another admin uses Set password (setAdminPassword). Own password: My account (changeOwnPassword, checks the current password first).
  3. Nobody can log in: npm run admin:password -- you@gmail.com on a computer with .env.local prints a temporary password.
  4. /admin loads; requireAdmin() confirms the email is still in admins.
  5. Optional: "Continue with Google" (signInWithGoogle) when NEXT_PUBLIC_GOOGLE_AUTH_ENABLED=true.

Rules and edge cases

  • Team members never need to log in.
  • No emails are sent, so there is no email rate limit and no dependency on the Supabase Site URL.
  • Passwords are 8–72 characters and are stored by Supabase Auth (hashed), never in the app database.
  • Locally without Supabase, DEV_ADMIN_EMAIL acts as the signed-in admin (development only).
