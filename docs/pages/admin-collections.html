Admin page

Collections

Tournament shares, monthly fees and special collections charged to a chosen list of players.

Purpose and access

admin only

Admins only. proxy.ts redirects anonymous visitors to /login; the page calls requireAdmin() before loading data, and every action re-checks through adminAction().

URL and query parameters

URL / parameterMeaning
/admin/collectionsList and New collection form.
/admin/collections/[id]One collection (collections.id).

What is shown

  • List — each collection with type, due date, players, charged / paid / due.
  • New collection — type (tournament, monthly, special, other), title, description, due date, amount per player, player checklist (Select all / Active members / Clear; active members ticked by default).
  • Detail — totals; per-player rows with editable amount, status, mark paid / unpaid, waive; player-list editor; delete.

Actions

Every action below is a server action wrapped by adminAction() (src/lib/action.ts): admin check → zod validation → one database transaction → audit_log entry → refresh() → Google Sheet rewrite after the response (after(() => syncSheet("change"))).

ControlServer actionWhat happens
CreatecreateCollectionInserts collections and one collection charge per player (admin-locked, dated due_on); applies credit
Save player listsetCollectionPlayersDeletes charges for removed players, adds charges for new ones
Amount / paid / unpaid / waiveupdateChargeAmount, markPaid, markUnpaid, waiveChargeSame ledger functions as match fees
Delete collectiondeleteCollectionDeletes the collection and its charges (cascade); any money paid becomes credit

Rules and edge cases

  • Use a collection for every tournament (e.g. ₹400 SPARTANS share) — tournament matches are not auto-charged.
  • Collection charges appear on the public Finance page and in the sheet's Collections tab.
