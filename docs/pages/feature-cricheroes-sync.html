CricHeroes sync

How matches, players, scorecards and match-fee charges come from CricHeroes into the database.

Purpose and access

feature

URL and query parameters

URL / parameterMeaning
https://cricheroes.com/team-profile/2921535/team/matchesLatest 12 matches → parseTeamMatches
https://cricheroes.com/team-profile/2921535/team/membersSquad with photos (34 players at build time) → parseTeamMembers
https://cricheroes.com/scorecard/&lt;matchId&gt;/match/match/scorecardScorecard (slug segments are ignored) → parseScorecard

What is shown

cricheroes.com is a Next.js site. Page data is embedded as self.__next_f.push([1,"…"]) chunks. decodeRscPayload() joins and unescapes them, parseRscObjects() parses each JSON line, and the parsers find the objects by their keys (match_id + team_a_id; player_id + profile_photo + is_captain; scoreCardData). The private CricHeroes API key is not used.

Steps of runCricheroesSync(trigger)

  1. Insert a sync_runs row (kind cricheroes, status running).
  2. Squad: upsert members by cricheroes_player_id. New → is_member = true. Existing → refresh ch_name, ch_photo_url, styles, captain; name only if not name_locked. Failure here is a warning.
  3. Matches: fetch the list (0 matches = error, the page format may have changed), keep matches on/after sync_start_date, upsert each by cricheroes_match_id: status, result, outcome (matchOutcome), opponent, scores, ground… Unless finance_locked: set kind (defaultMatchKind) and chargeable (isChargeableByDefault); set fee_per_player from settings only while the match is new or not yet past.
  4. Scorecard for past matches never synced, or within 3 days of the match (SCORECARD_REFRESH_DAYS): extractTeamPerformance builds our XI (our batting card + yet to bat + our bowlers) with batting, bowling and fielding (catches / stumpings / run outs matched by name from dismissal texts). Unknown players are created as guests (is_member = false). Upserts match_players and player_match_stats; removes CricHeroes-sourced, non-locked roster rows that are no longer on the scorecard.
  5. Charges: reconcileMatchCharges per match in its own transaction.
  6. Close the run with status success and the summary (or failed + error).

Data flow

sequenceDiagram
  autonumber
  participant J as Cron or Sync now
  participant S as runCricheroesSync
  participant C as cricheroes.com
  participant D as Postgres
  J->>S: trigger
  S->>D: sync_runs (running)
  S->>C: members page
  S->>D: upsert players
  S->>C: matches page (latest 12)
  loop each match since sync_start_date
    S->>D: upsert match (respect finance_locked)
    opt past and (never synced or within 3 days)
      S->>C: scorecard page
      S->>D: match_players + player_match_stats (respect admin_locked)
    end
    S->>D: reconcileMatchCharges
  end
  S->>D: sync_runs (success + summary)

Rules and edge cases

  • Idempotent: re-running never duplicates matches, stats or charges.
  • A missing scorecard is a warning ("add players manually"), not a failure.
  • Only the latest 12 matches are visible; a nightly run is far more frequent than the team plays 12 matches.
  • Upcoming matches are stored (for the dashboard's next fixture) but never charged.
