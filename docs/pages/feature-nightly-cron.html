Feature

Nightly cron

The scheduled job that refreshes CricHeroes data and rebuilds the Google Sheet every night.

Purpose and access

feature

URL / parameterMeaning
GET /api/cron/nightlyRequires header Authorization: Bearer $CRON_SECRET; otherwise 401.

What is shown

// vercel.json
{ "regions": ["sin1"], "crons": [{ "path": "/api/cron/nightly", "schedule": "0 18 * * *" }] }

0 18 * * * = 18:00 UTC = 23:30 IST. On Vercel's Hobby plan the job runs once a day, at some point within that hour. Vercel sends the CRON_SECRET environment variable automatically.

  1. Check the secret.
  2. On Vercel: CricHeroes is skipped — Cloudflare shows every cloud server a robot check (HTTP 403), so the sync helper on the team Mac runs the CricHeroes part (see below). Elsewhere: runCricheroesSync("cron"), errors caught and reported.
  3. syncSheet("cron") — always runs, so admin edits are mirrored even if CricHeroes failed.
  4. Return JSON with both results; HTTP 500 if CricHeroes failed (visible in Vercel's cron logs).

The sync helper (team Mac)

scripts/sync-agent.ts runs as a launchd service on the Mac (npm run sync:agent:install; log ~/Library/Logs/viking-warriors-sync.log; remove with npm run sync:agent:uninstall). Every 30 s it:

  1. Writes a heartbeat (settings.sync_agent_seen_at) — Admin → Sync & logs shows it Online / Offline.
  2. Fails runs stuck in running over 20 min; skips queued requests older than 6 h.
  3. Claims each queued request from the live “Sync CricHeroes now” button and runs the sync + Sheet rebuild into that same sync_runs row.
  4. Runs the nightly sync if the latest 23:30 IST slot has no successful cron run (catches up when the Mac wakes; a failure retries after 30 min, 3 tries a night).

CRICHEROES_SYNC_VIA=agent|direct overrides the mode (default: agent on Vercel, direct elsewhere). Code: src/modules/sync/queue.ts.
