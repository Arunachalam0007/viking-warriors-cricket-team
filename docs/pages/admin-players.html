Admin page

Manage players

Edit names, phone numbers, photos, member / guest and active status; add players who are not on CricHeroes.

Purpose and access

admin only

Admins only. proxy.ts redirects anonymous visitors to /login; the page calls requireAdmin() before loading data, and every action re-checks through adminAction().

URL and query parameters

URL / parameterMeaning
/admin/playersNo parameters; search and filter chips are client-side.

What is shown

  • Search box and filter chips: Members, Guests, Inactive, All.
  • Card per player: photo, name, CricHeroes name when different, phone, member / guest, active, captain.
  • Edit dialog: name, phone, member, active, notes, photo upload, "Use CricHeroes photo".
  • Add player dialog: name, phone, member.

Actions

Every action below is a server action wrapped by adminAction() (src/lib/action.ts): admin check → zod validation → one database transaction → audit_log entry → refresh() → Google Sheet rewrite after the response (after(() => syncSheet("change"))).

ControlServer actionWhat happens
SaveupdatePlayerUpdates name / phone / is_member / is_active / notes. Renaming sets name_locked. Switching member ↔ guest reruns reconcileMatchCharges for every match the player played
Upload photouploadPlayerPhotoImage ≤ 3 MB → Supabase Storage bucket player-photos (created if missing) → players.photo_url. Not wrapped by adminAction but calls requireAdmin and audit itself
Use CricHeroes photoresetPlayerPhotoClears photo_url
Add playercreatePlayerInserts a player without a CricHeroes id (name locked)

Rules and edge cases

  • Phone numbers are stored for WhatsApp reminders (phase 2) and never shown publicly.
  • Photo upload needs SUPABASE_SECRET_KEY; without it the action returns a clear error.
