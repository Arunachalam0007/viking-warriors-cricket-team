Admin page

Payments

Record money received, see every player's balance, add opening balances / adjustments, and manage payment history.

Purpose and access

admin only

Admins only. proxy.ts redirects anonymous visitors to /login; the page calls requireAdmin() before loading data, and every action re-checks through adminAction().

URL and query parameters

URL / parameterMeaning
/admin/paymentsNo parameters.

What is shown

  • Record payment form — player (with current balance), amount, date, mode, received by, reference, note.
  • Balances — every player: charged, paid, balance; sortable; "Record payment" pre-fills the form.
  • Adjustment / opening balance — one-off charge for a player (e.g. dues carried over from the old sheet).
  • Payment history — last 200 payments with player, amount, mode, holder, reference; delete.

Actions

Every action below is a server action wrapped by adminAction() (src/lib/action.ts): admin check → zod validation → one database transaction → audit_log entry → refresh() → Google Sheet rewrite after the response (after(() => syncSheet("change"))).

ControlServer actionWhat happens
Record paymentrecordPaymentActionrecordPayment: inserts a manual payment, then applyCredit settles the oldest open charges; extra stays as credit
Add adjustmentaddAdjustmentInserts an adjustment charge (admin-locked) and applies any credit
Delete paymentdeletePaymentActionDeletes the payment (allocations cascade) and re-applies remaining credit

Rules and edge cases

  • Amounts are whole rupees, at least ₹1.
  • A player's balance below zero is credit and is used automatically for future charges.
